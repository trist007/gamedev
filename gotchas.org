** Debugging notes
Check what a library's linker search actually resolves to:

ld -o /dev/null -lvolk --verbose 2>&1 | grep -i "attempt\|found"

Shows every path the linker tried for -lvolk, revealing whether a stray system/SDK copy would shadow your own compiled object.

Find files by name pattern under a directory:

find /path/to/sdk/lib -iname '*volk*'

Caught the SDK's bundled libvolk.a sitting in the Vulkan SDK's lib/ — the actual duplicate-symbol source, missed by the plain ld test since that didn't include the SDK's -L path.

Check what shared libraries a binary actually links against:

ldd ../bin/wing | grep -i vulkan

Confirmed whether wing was using the distro loader (/usr/lib/libvulkan.so.1) or one from the SDK.

List exported symbols in a shared object:

nm -D libgame.so | grep -i game

-D shows the dynamic symbol table (what's visible to dlsym/other binaries at runtime) rather than the full symbol table. Confirmed initGame, updateGame, renderGame, runGame, and the game_api struct were all properly exported.

Vulkan loader verbose diagnostics:

VK_LOADER_DEBUG=all ./wing 2>&1 | grep -iE "icd|layer|error"

The loader has its own internal logging separate from your app's LOG() calls — this traces every ICD manifest and layer manifest it searches for, where, and why each one succeeded/failed/got skipped (e.g. arch mismatch). This is what pinpointed both the missing 64-bit Intel ICD and the missing validation layer manifest, before either was visible any other way.
